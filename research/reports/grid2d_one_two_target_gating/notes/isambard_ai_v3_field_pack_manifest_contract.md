# Isambard-AI v3 field-pack and manifest contract

Status: implementation and local small-pack tests complete; the 32-field
production pack and production manifests are intentionally not generated by
this implementation task.

## Fixed output paths

Running the generator and builder with their defaults writes:

- `artifacts/data/disorder_field_pack_v3.npz`;
- `artifacts/data/disorder_field_pack_v3.manifest.json`;
- `artifacts/data/gating_v3_canary_manifest.json` (8 local cells, IDs 0--7);
- `artifacts/data/gating_v3_production_manifest.json` (5,760 cells for the
  default 32-field pack, IDs 0--5,759);
- `artifacts/data/gating_v3_tail160k_manifest.json` (384 cells for the default
  pack, IDs 0--383, all using profile `tail_160k`).

The tail manifest is frozen in advance but must not enter the first submission
chain. Submit it only if the independently verified 80,000-step reducer tail
gate returns `FAIL`.

## Field definition

For field index `i`, the generator uses seed `20260726 + 7919*i` and explicitly
constructs `numpy.random.Generator(numpy.random.PCG64(seed))`. It draws float64
standard-normal white noise, applies
`scipy.ndimage.gaussian_filter(sigma=4, mode="reflect", order=0, truncate=4)`,
subtracts the spatial mean, and performs a deterministic residual correction.
The stored C-order little-endian float64 field has:

- exactly zero `math.fsum` over all cells;
- exactly `max(abs(field)) == 1.0`;
- one seed, sigma, array hash, timing, and numerical-statistics record per
  field;
- generator-source, NumPy, SciPy, Python, platform, full-pack, and member
  hashes in the sidecar manifest.

The NPZ writer fixes ZIP timestamps and member order. Consequently, a fixed
NumPy/SciPy runtime produces identical pack bytes, while the sidecar still
records the actual runtime so cross-version changes cannot be hidden.

## Campaign mapping and common random numbers

The production geometry index and cell ID are

```text
geometry_index = x_index * 5 + y_index
cell_id = ((((geometry_index * 6) + amplitude_index) * field_count
            + field_index) * 2 + stream_index)
```

The geometry loops are target-2 `x=[24,32,40]`, `y=[9,16,24,31,38]`;
amplitudes are `[0,.05,.10,.15,.20,.25]`; streams are `[0,1]`. The walk seed
is `1729 + field_index*104729 + stream_index*1009`, deliberately excluding
geometry and amplitude. Thus each field/stream pair supplies common random
numbers across geometry, amplitude, and the coupled one-/two-target systems.
Streams are averaged within a field; the inference sample size is the number
of fields, never twice that number.

The builder reads the domain from `contrasts.shape`, then requires the frozen
production shape to be `(field_count,48,64)`. Field count is accepted from 2
through 128. The default 32 fields produce 5,760 production cells; a later
128-field pack produces 23,040 cells and requires a separately approved
resource allocation.

## Frozen inference and gates

The primary geometry is target 2 at `(32,24)` and the primary amplitude
contrast is `0.20 - 0.00`. The 95% interval decision uses an absolute
probability ROPE of `[-0.002,+0.002]`: negative only above/below the negative
boundary, positive only beyond the positive boundary, equivalent only when
the complete interval lies inside the ROPE, and inconclusive otherwise.

Integrity validation fails closed on missing or duplicate tasks, artifact hash
mismatch, nonfinite values, holding probabilities outside `[0,1)`, fixed-mean
or mass-balance error above `1e-12`, paired-subset violations, nonmonotone
checkpoints, task-map mismatch, and runtime-parameter mismatch. The tail gate
requires both unresolved 95% upper bounds at most `0.005` and
`abs(mean(G_T-G_T/2)) + tcrit*SE <= 0.002`. Failure at 160,000 steps forbids an
asymptotic claim and leaves only finite-horizon and explicit tail-bound claims.

The stage counts for 32 fields are G0=8, A=384, conditional A2=384, B1=1,536,
B2=1,280, and B3=2,560. The manifest freezes the measured-runtime allocation
model, stage caps, a conditional precision cap, reserve, and the 950 node-hour
campaign ceiling.

## Production commands

From the report directory, generate the 32-field pack with the declared SciPy
implementation:

```bash
uv run --no-project --with numpy --with scipy python3 code/generate_disorder_field_pack_v3.py
```

Then build all three no-placeholder manifests using the already audited
Isambard container identity:

```bash
python3 code/build_gating_campaign_manifest_v3.py \
  --container-reference /projects/public/brics/containers/e4s/e4s-cuda90-aarch64-25.11.sif \
  --container-sha256 aac14468290a4b1489806a47e26ada96b741afbbe2edfe8fa2bf5424013f09c4
```

The builder hashes the actual pack, sidecar, runner, builder, validator, and
container identity; missing, all-zero, or textual placeholder hashes are
rejected. It writes each manifest atomically and immediately runs the strict
validator against the live pack, sidecar, and runner source.

Revalidate before payload hashing or upload:

```bash
python3 code/validate_gating_campaign_manifest_v3.py \
  --manifest artifacts/data/gating_v3_canary_manifest.json
python3 code/validate_gating_campaign_manifest_v3.py \
  --manifest artifacts/data/gating_v3_production_manifest.json
python3 code/validate_gating_campaign_manifest_v3.py \
  --manifest artifacts/data/gating_v3_tail160k_manifest.json
```

The validator exhaustively reconstructs every expected cell, round-trips the
production task mapping, audits the common-random-number seed groups, compares
the full preregistration including ROPE and gates, rejects placeholders, and
checks every live artifact hash supplied by the default paths.
